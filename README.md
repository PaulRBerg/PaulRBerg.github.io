# PaulRBerg.github.io

[![Deploy to GitHub Pages](https://github.com/PaulRBerg/PaulRBerg.github.io/actions/workflows/deploy.yml/badge.svg)](https://github.com/PaulRBerg/PaulRBerg.github.io/actions/workflows/deploy.yml)

PRB's personal site, blog, and presentation archive at [prberg.com](https://prberg.com).

Source files were migrated from [prb-site](https://github.com/PaulRBerg/prb-site) without importing
its Git history. Existing presentation URLs and destination-only authoring material are preserved.

## Development and deployment

Run `bun install --frozen-lockfile` from the repository root. Use `just dev` for development,
`just build` for the production build in `dist/`, and `just preview` to inspect that build. Run
`just full-write` and `just full-check` before committing.

Push to `main` to deploy through
[GitHub Pages](https://github.com/PaulRBerg/PaulRBerg.github.io/actions/workflows/deploy.yml). The
workflow caches Astro assets and both Slidev decks. It rebuilds the decks when their sources or
build configuration change, and rebuilds the Astro site and Pagefind search index on every run.
`public/CNAME` preserves the custom domain, and the Pages artifact includes `.nojekyll`.

## Reading experience

Articles generate their table of contents from headings and offer reading progress, font and size
preferences, image zoom, footnote previews, and links to individual headings. Reading preferences
apply to article prose; navigation and code retain the site's monospace font.

Store article images in `src/assets/posts/<year>/<slug>/` and use relative Markdown image paths so
Astro emits responsive, optimized images with dimensions. Reference `ogImage` previews from the same
directory with relative paths. Image zoom opens the widest responsive variant, which keeps the
source's full dimensions. The article image plugins prioritize the first image and lazy-load the
remaining images.

Code fences use [Expressive Code](https://expressive-code.com/) with theme-aware highlighting,
wrapping, and copy buttons. Add `title="example.ts"` for an editor frame, `showLineNumbers` to
enable line numbers, or `collapse={1-5}` to fold a range of lines. Collapsed sections can be opened
and closed again. Plain text blocks omit line numbers by default.

Open search from the header or with ⌘K / Ctrl+K. The `/search?q=term` page supports shareable
queries; results include matching sections and highlight the searched terms in article prose. Search
uses the Pagefind index generated by `just build`, so run a build before testing search in
development.

## Presentations

The presentation archive is linked from [`/speaking`](https://prberg.com/speaking). The eight legacy
decks retain their original `/presentations/<slug>/` URLs, `index.html` entry points, and slide
hashes.

Editable sources live in `slides/`. The HTML decks share an Astro layout and bundled Reveal.js
runtime, with their original themes and media in `public/presentations/<slug>/`. The CCE and
Frontiers 2026 decks retain their Slidev Markdown, Vue components, and assets.

Historical PDF, PowerPoint, and Keynote decks live in `public/presentations/<slug>/` and are linked
directly from the speaking page. PDFs open in the browser; PowerPoint and Keynote links download the
original files. Speaking resource links open in new tabs while native files retain their download
behavior.

`just dev` and `just build` first build both Slidev decks into ignored
`public/presentations/<slug>/` directories. `bun run build:slides` rebuilds just those decks. Astro
then builds the site and Reveal pages using the npm Reveal.js runtime. The retained legacy submodule
is excluded from the build and code checks.

The Slidev builds set their own HTML base URLs so images also work on slashless legacy links. The
`floating-vue` override retains the API expected by Slidev's syntax-tooltip integration.
